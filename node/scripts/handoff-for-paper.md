## 1. System Architecture

### Smart Contracts (Solidity, deployed on EVM)

| Contract | Address | Role |
|----------|---------|------|
| `Groth16Verifier` | auto-generated by snarkjs | Pairing-based ZK proof verification (Yul/assembly) |
| `ZKVerifier` | `0xe7f1725E7734CE288F8367e1Bb143E90bb3F0512` | Wrapper: validates 3 public inputs (preStateHash, postStateHash, valid) |
| `RollupManager` | `0x9fE46736679d2D9a65F0992F2272dE9f3c7fa6e0` | State root proposal, batch finalization, challenge period management |
| `DisputeManager` | `0xCf7Ed3AccA5a467e9e704C703E8D87F634fB0Fc9` | Dispute lifecycle: initiate, bisect, submit proof, resolve, timeout |

### ZK Circuits (Circom 2, Groth16 via snarkjs)

| Circuit | Purpose |
|---------|---------|
| `mips_single_step.circom` | Main: proves correctness of one MIPS state transition |
| `mips_alu.circom` | ALU operations (ADD, SUB, AND, OR, XOR, SLT, shifts, mult/div) |
| `mips_memory.circom` | Memory read/write with Merkle proof verification |
| `mips_utils.circom` | Bit manipulation, range checks, multiplexers |

- Proof system: **Groth16** (BN128 curve)
- Constraint count: ~65,000
- Public inputs: 3 (preStateHash, postStateHash, valid)

### Off-chain VM (TypeScript, ported from Cannon FPVM)

- **ISA**: MIPS32 subset — 43 instructions (25 R-type, 16 I-type, 2 J-type)
- **State**: 32 registers, PC, nextPC, HI, LO, heap, memory Merkle tree
- **State hash**: Keccak256 of packed state (matches on-chain representation)

## 4. Performance Comparison

### Table: Traditional Optimistic Rollup vs SI-RVP (SI-RVP)

| Metric | Traditional | SI-RVP | Improvement |
|--------|-------------|--------|-------------|
| Dispute resolution time | 7 days (604,800,000 ms) | ~17s (17,300 ms) | **-100.00%** |
| On-chain messages | 73 | 5 | **-93.15%** |
| Total gas cost | 3,650,000 | 803,725 | **-77.98%** |
| Gas per message | 50,000 | 160,745 | N/A (different model) |

### Notes on Traditional Baseline

The traditional values are theoretical estimates based on:
- 7-day challenge period (standard Optimistic Rollup, e.g., Optimism, Arbitrum)
- 73 on-chain messages: full interactive bisection for N=10 steps requires O(N) messages in worst case, plus state submissions
- 50,000 gas per message: average cost of a simple state hash submission transaction

### Notes on SI-RVP Measured Values

- **5 messages**: propose → initiate → bond → bisect → prove (entire dispute lifecycle)
- **~17s**: off-chain bisection (3 rounds x 100ms) + proof generation (~15s) + submission (~2s)
- Proof generation time is dominated by Groth16 witness computation and MSM (not measured on-chain)

## 6. Gas Cost Breakdown (for charts)

### Pie Chart Data

```
proposeStateRoot:      122,234  (15.2%)  -- Sequencer posts state root
initiateDispute:       274,243  (34.1%)  -- Challenger opens dispute + stores params
depositSequencerBond:   46,098  ( 5.7%)  -- Sequencer deposits 0.01 ETH bond
submitBisectionResult:  88,237  (11.0%)  -- Submit off-chain bisection result
submitProof:           272,913  (34.0%)  -- Groth16 proof verification on-chain
```

### Key Insight

The two most expensive operations are `initiateDispute` (34.1%) and `submitProof` (34.0%). The Groth16 pairing check dominates the proof submission cost. Together they account for **68.1%** of total gas, while the actual state management (`proposeStateRoot` + `depositBond` + `submitBisection`) is only **31.9%**.

## 9. How to Reproduce

```bash
# 1. Deploy contracts and run E2E test
cd contracts
npx hardhat node &
npx hardhat run scripts/deploy.ts --network localhost
npx hardhat test test/ZKVerifier.onchain.test.ts --network localhost

# 2. Generate dashboard data from on-chain results
cd ../node
npm run export:dashboard

# 3. View dashboard
cd public && python3 -m http.server 8080
# Open http://localhost:8080/dashboard.html
```
